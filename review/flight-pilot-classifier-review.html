Direct daemon orchestration

Agent communication now stays inside the daemon. The worker subscribes to the assigned pilot and planner chat streams. Only planner turns go to Jev. The pilot returns a structured final decision; intermediate commentary remains evidence but is not the decision. The daemon validates the source pilot, current planner, workspace membership and delivered notification before persisting guidance and sending it directly through the chat runtime.

The user CLI command, its tests, dispatch branch, HTTP route, request/response contracts, shell instructions and obsolete implementation plan were removed. The CLI entry point and CLI guide have no diff from the original repository. Earlier recommendations concerning the removed command no longer apply.

internal/flights/pilot_test.go:9 checks structured decisions, invalid/prose responses, unknown recipients, missing notifications, stale sources, stopped planners, workspace mismatch, interrupted responses and replay deduplication. The monitor round-trip test now drives completed pilot chat output rather than invoking an external return path. Test-rules review: compliant for these changes. Both new and retained checks use the Quick backend gate. Retry/attempt scanner hits describe product operations or evidence; the monitor deadline exceptions await shutdown and HTTP-start events and fail on expiry.

Must fix

1. P0 The real daemon never constructs the monitor

Evidence: internal/flights/manager.go:142, internal/flights/manager.go:169, internal/daemon/flights.go:25, internal/flights/monitor.go:56.

The constructor creates the monitor only when Dependencies.Chats is already supplied. Daemon initialization omits it; later Bind sets Chats but never constructs the subsystem. StartMonitoring therefore returns immediately. Existing test constructors supply Chats up front and conceal this difference.

Fix: initialize the subsystem independently of early chat binding and start it after collaborators are bound. Add a test using the actual construct-then-bind sequence. Without it: none of the four flights gets classified.

2. P1 Jev requests use an incompatible schema

Evidence: internal/flights/monitor_jev.go:87, internal/flights/monitor_jev.go:93, internal/flights/monitor_config_test.go:221.

The implementation sends questions as an array and each criteria as an array of ID/description objects. The current official API requires questions keyed by question ID and criteria keyed by option ID. The mock test explicitly expects the incompatible arrays.

Fix: encode the documented keyed objects while preserving choice order, and make the HTTP fixture validate that contract. Without it: successful mock responses cannot establish that real Jev requests work.

3. P1 Monitor notifications never reach the pilot

Evidence: internal/flights/monitor.go:272, internal/flights/monitor.go:321, internal/flights/monitor_model.go:95, internal/flights/monitor.go:280.

buildNotification leaves the recipient empty, so interesting classifications fail with recordFlightMessage requires recipient. Failed-turn notifications supply the recipient but only append a pending flight record. Neither branch calls a chat send, and no worker drains pending messages.

Fix: set the current pilot recipient and send through one persisted delivery path. Test that an interesting ruling appends a message to the pilot conversation, not merely to flight history. Without it: the pilot waits forever for notifications.

4. P1 The classifier file resolves to the wrong location

Evidence: internal/flights/monitor.go:19, internal/flights/monitor.go:64, internal/flights/monitor.go:243.

The path is the literal relative string $SCHMUX_HOME/flight-monitor.yaml. Go filesystem calls do not expand environment variables. The worker will create/read a directory named $SCHMUX_HOME under its working directory, while edits to the documented ~/.schmux/flight-monitor.yaml have no effect.

Fix: derive the path from schmuxdir.Get(), keeping test overrides instance-local. Without it: the primary classifier-tuning workflow edits a file the monitor never reads.

5. P1 Planner turns are attributed to the pilot; replacement sessions share a cursor

Evidence: internal/flights/monitor.go:197, internal/flights/monitor.go:205, internal/flights/monitor.go:216, internal/flights/monitor.go:343.

The consumer constructs its collector with the pilot ID and overwrites every emitted turn with the current pilot ID. The resume boundary then takes the largest EndSeq across all retained sessions. A replacement planner whose log has fewer records can be skipped or collide with an earlier work key; source links identify the wrong conversation.

Fix: retain the observed planner ID, derive its own boundary, and reconcile subscriptions by assignment as well as flight ID. Without it: evidence is misattributed and planner replacement can lose classifications.

6. P1 Retry and restart do not execute pending work

Evidence: internal/flights/monitor_model.go:229, internal/flights/monitor_model.go:250, internal/flights/monitor.go:134, internal/flights/monitor.go:168.

Retry only changes a failed turn/message to pending. Reconciliation returns when a flight already has a worker; no loop scans persisted pending items. After restart, subscription resumes after a retained turn even if its classification never finished. Queued pilot messages likewise have no delivery observer, and sending records are not converted to unknown on load.

Fix: add the planned worker that drains persisted pending work and reconciles delivery outcomes independently of new planner output. Test another HTTP request after Retry and recovery after a retained-but-unclassified turn. Without it: the Retry button can report success while doing nothing, and interrupted work remains stuck.

7. P1 Subscription workers ignore cancellation and block on classification

Evidence: internal/flights/monitor.go:192, internal/flights/monitor.go:209, internal/flights/monitor.go:261, internal/flights/monitor.go:134.

The live loop ranges over the channel without selecting on context or unsubscribing. Cancelling a flight cannot release a quiet worker; later output can still reach the old handler. Jev runs synchronously inside that same record-consumption loop. Existing worker entries also ignore changed pilot/planner IDs, and exited workers are never removed from the registry.

Fix: consume with context cancellation and deferred Unsubscribe, keep HTTP in the separate pending-work worker, and replace/remove subscriptions when their assignments change or exit. Without it: stopping or replacing a planner leaves stale monitoring, and slow classification stalls ingestion.

8. P1 Takeoff can reuse a pilot from another workspace

Evidence: internal/flights/transitions.go:235, internal/flights/transitions.go:251, internal/flights/transitions.go:309, internal/workspace/manager.go:547.

Takeoff overwrites the workspace assignment before deciding whether to reuse the pilot. Reuse checks only whether the pilot is running, not where it runs. This matters on normal retry: the workspace allocator does not reuse a workspace with active sessions, so a surviving pilot can lead to a new workspace while the old pilot remains attached.

Fix: preserve/reuse the recorded live workspace on retry and verify actual pilot workspace membership before reuse. Persist successful pilot assignment before attempting planner spawn. Without it: the pilot supervises a planner in a different checkout, with stale paths and context.

9. P2 Returned flight copies share mutable classification evidence

Evidence: internal/flights/model.go:295, internal/flights/monitor.go:312.

clone copies the Attempts slice but retains its Config and Classification pointers and their nested slices/maps. A caller can mutate manager state through a returned copy, without persistence or locking. The notification builder also sorts a shared Answers slice after the classification was retained.

Fix: deep-copy the retained nested evidence on insertion and return; do not sort shared state. Without it: recorded evidence can change outside the sole-writer path and race readers.

10. P2 A real Codex interruption is reported as successful completion

Evidence: internal/flights/monitor_turns.go:302, assets/dashboard/src/lib/chat/__fixtures__/codex/interrupt.out.jsonl, internal/flights/testdata/monitor/codex_two_turns.jsonl:3.

The parser maps only failed status; interrupted becomes completed. Replaying the repository's recorded interruption reproduces this. Its synthetic tests also put turn IDs at params.turnId, while real turn start/completion records use params.turn.id; this leaves active-turn tracking empty and causes item-completion records with real IDs to be ignored.

Fix: consume the actual recorded protocol shapes and preserve interrupted status. Without it: an interrupted planner can be silently skipped as an empty successful turn instead of notifying its pilot.

Should fix

11. Question snapshots are hidden from inspection

Evidence: internal/api/contracts/flights.go:113, internal/dashboard/handlers_flights.go:159, assets/dashboard/src/routes/flights/FlightMonitorHistory.tsx:137, internal/flights/monitor.go:306.

Although attempts retain Config, the API strips it and the history shows only question IDs, choices and confidence. Notifications omit the question text, artifact path and conversation path promised to the pilot.

Fix: expose the retained question/choice snapshot and include the required source paths in notifications. Without it: after editing YAML, users cannot inspect the exact questions behind an older ruling, and the pilot lacks its promised evidence references.

12. Core monitoring tests are absent and existing subscription tests were removed

Evidence: internal/chat/runtime_sequence_test.go:1, internal/flights/monitor_config_test.go:221, internal/flights/monitor_model_test.go:196, internal/flights/pilot_test.go:9.

The change replaces five pre-existing sequence/subscription tests with send-status tests. There is no monitor-loop test file, no successful manager pilot-to-planner test, and the retry test checks only the pending flag. The API mock validates the implementation's wrong schema. These gaps explain why the reported tests pass with the core path disconnected.

Fix: restore the five original tests; add deterministic construct/bind/start, classification-to-pilot-chat, retry/recovery, and successful return-path tests with a contract-validating fake Jev endpoint. Without it: passing unit counts continue to give no evidence for the requested round trip.
