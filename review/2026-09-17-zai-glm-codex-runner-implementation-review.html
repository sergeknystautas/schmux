Deviations from the plan — all verified correct

1. Resume model-flag re-injection dropped (the big one)

The plan had session and floormanager resume paths manually append -m <model>. The agent dropped that, claiming BuildCommandParts already injects it. Verified against source: expandModelPlaceholder (adapter_generic.go:535-539) appends [modelFlag, modelValue] when the args template has no {model} placeholder — codex's resume --last template has none, so resume already carries the flag. The plan's block would have produced -m glm-5.3 -m glm-5.3.

Empirical confirmation (throwaway probe, since deleted): the built resume command is 

codex resume --last -m glm-5.3 -c model_provider=zai -c model_catalog_json=<path>

— exactly one flag, provider args after it. This was a bug in my plan: the spec's claim that InteractiveArgs(model, resume=true) "returns just the descriptor's resume_args — no model" holds only when the model is nil, and the resume path passes a model.

2-3. Test-fixture fixes

  • Config{Models: …} doesn't compile — Config embeds ConfigData (config.go:150). Fixed to Config{ConfigData: config.ConfigData{Models: …}}. verified
  • secrets.json fixture needed a "models" key — LoadSecretsFile only takes the new-format path when that key is present (secrets.go:75); without it the fixture parses as legacy and the provider secret is invisible. verified
  • Scalar-vs-list YAML in TestBuildRunnerArgsModelPlaceholder — plan wrote '--route={model}' as a scalar where the struct wants a list; fixed to a list item. self-evident

4. Unreported: RequiresOpenaiAuth *bool instead of the plan's bool

The plan's readiness snippet (case !r.RequiresOpenaiAuth with a plain bool) would treat field-absent as logged-in — contradicting the spec and failing the plan's own TestCodex_NullAccountWithoutFieldStaysLoggedOut. The pointer type with r.RequiresOpenaiAuth != nil && !*r.RequiresOpenaiAuth is the minimal correct form. The agent didn't list this among their deviations; it's a necessary fix, correctly applied. verified
